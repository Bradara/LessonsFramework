Капсулация

Информатика - Модул 1

След този урок ще можеш да:
  • обясниш какво е капсулация и защо е полезна;
  • използваш private, public и internal и да избираш подходящия модификатор;
  • хвърляш и хващаш изключения с throw и try/catch;
  • валидираш данни в setter-и и конструктори, така че обектът винаги да е във валидно състояние.

Какво е капсулация?

Телевизорът има бутони и дистанционно, но не е нужно да отваряш кутията и да пипаш платката. Бутоните са публичният интерфейс, платката е скритата имплементация. Така не можеш да счупиш телевизора по погрешка, а производителят може да смени платката, без да променя дистанционното.

  • Капсулацията е процесът на обединяване на кода и данните в едно цяло.
  • Скрива детайлите и показва само публичен интерфейс.
  • Позволява валидация на данните и контрол над достъпа.

Капсулацията е един от четирите стълба на обектно-ориентираното програмиране.

Без капсулация

  • всеки може да запише person.age = -5;
  • ако смениш името на полето, се чупи целият код, който го ползва;
  • няма къде да сложиш проверка на данните.

С капсулация

  • структурните промени остават локални – външният код не се засяга;
  • намалява се комплексността – ползвателят знае само интерфейса;
  • обектът е винаги във валидно състояние.

Модификатори за достъп

Модификаторът казва кой има право да използва даден член на класа. Избери модификатор и виж откъде е достъпен.

МодификаторКакво трябва да знаеш
privateОсновният начин да скрием данните от външния свят. Подразбиращ се за полета и методи.
publicНай-високото ниво на достъп – няма ограничения. Така се показва публичният интерфейс.
internalПодразбиращ се за всеки клас. Достъпен от всеки друг клас в същия проект.

Класовете и интерфейсите обикновено са public или internal (private е възможен само за вложени типове), затова избягвай да ги декларираш като частни.

Достъп до публичен клас от друго пространство от имена

За да достъпиш класа директно от namespace, използвай using.

namespace Mathematical
{
    public class Basic
    {
        public static double PI = 3.14;
    }
}

using System;
using Mathematical;

namespace Distinct
{
    public class Program
    {
        static void Main()
        {
            Console.WriteLine(Basic.PI);
        }
    }
}

Достъп в същия проект – internal

class Person                     // internal по подразбиране
{
    internal string Name { get; set; }
    internal int Age { get; set; }
}

// в друг клас от същия проект:
Team rm = new Team("Real");
rm.Name = "Real Madrid";

Свойства с private set и метод ToString()

{ get; private set; } означава: всеки може да чете стойността, но само класът може да я променя. За да покажем данните на обекта на екрана, ги превръщаме в string – презаписваме метода ToString() с override. 

public class Student
{
    public string FirstName { get; private set; }
    public string LastName { get; private set; }

    public override string ToString()
    {
        return $"The student's name is {FirstName} {LastName}.";
    }
}

Изключения

  • Изключенията са грешки или проблеми, възникнали по време на изпълнение.
  • Можем да ги хвърлим (throw), за да сигнализираме за проблем.
  • Когато е хвърлено изключение, изпълнението спира (временно) и изключението се пренася по стека, докато стигне catch блок, който да предприеме действие.
  • Можем да го хванем с catch, да реагираме на грешката и да известим потребителя.
if (size < 0)
    throw new Exception("Size cannot be negative!");

try {
    size = int.Parse(text);
} catch (Exception ex) {
    Console.WriteLine("Invalid size!");
}

Валидация в getters и setters

Setter-ите са добро място за базова валидация на данните: пазим коректно вътрешно състояние.

Конструкторът присвоява стойностите през свойствата (с private setter-и и логика за валидация), а не директно на полетата. Така се гарантира валидно състояние на обекта още при създаването му. 

public Person(string firstName, string lastName, int age, decimal salary)
{
    FirstName = firstName;   // минава през setter-а
    LastName = lastName;
    Age = age;
    Salary = salary;
}

Задачи

Задача 1: Увеличение на заплатата

Разшири класа Person със Salary (заплата). Добави getter за Salary и метод, който увеличава Salary с определен процент. Хора, по-млади от 30, получават половината от стандартното увеличение.

Опитай първо сам, после виж решението:

public decimal Salary { get; private set; }

public void IncreaseSalary(decimal percentage)
{
    if (this.Age > 30)
        this.Salary += this.Salary * percentage / 100;
    else
        this.Salary += this.Salary * percentage / 200;
}

Проверка на решението: judge.softuni.org. Забележи: на точно 30 години условието Age > 30 не е вярно.

Задача 2: Валидиране на данни

Разшири класа Person с валидация за всяко поле:

  • имената трябва да имат поне 3 символа;
  • възрастта не може да бъде 0 или отрицателна;
  • заплатата не може да бъде по-малка от 460.
public int Age
{
    get => this.age;
    private set
    {
        if (value < 1)
            throw new ArgumentException("Age cannot be zero or negative!");
        this.age = value;
    }
}
// Допълни валидацията за останалите полета по същия начин

Проверка на решението: judge.softuni.org. Готовият клас можеш да изпробваш в Лабораторията.

Обобщение

  • Капсулацията скрива имплементацията и показва публичен интерфейс.
  • Полетата са private, свойствата са public; private set позволява промяна само отвътре.
  • Капсулацията намалява комплексността и гарантира, че структурните промени остават локални.
  • throw хвърля изключение, catch го хваща; без catch програмата спира.
  • Валидацията в setter-ите (и конструкторите през тях) пази вътрешното състояние на класа валидно.

Кликни върху възел, за да разгънеш/свиеш клона му. Плъзгай за преместване, скрол/бутоните долу вдясно за мащаб.

Работи с класа Person: създавай обекти, пробвай невалидни данни, викай IncreaseSalary и се опитай да променяш скритите данни отвън. Превключвателите вляво променят как е написан класът.
